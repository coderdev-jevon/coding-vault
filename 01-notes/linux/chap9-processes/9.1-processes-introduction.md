## * What is a Process?
==A program is the blueprint, process is one construction crew working for the blueprint==, and thread is individual workers inside the same crew.

A process needs computer resources, such as ==memory, CPU cycles== (total amount of CPU can work at the same time), and ==peripherals== (hardware like hard disk, printer).

## * Process Types
#### ** ==Interactive Processes==
Need to be started by the user him/herself (`Firefox, LibreOffic`)
#### ** ==Batch Processes== 
Fully detached from terminal, and it goes to queue (FIFO, First In First Out). Use ==`batch` or `at`==

```bash
batch 
shutdown -h +1
Ctrl + D # means end of input, start processing

at now +1 minute
shutdown -h now
Ctrl + D
```
#### ==** Daemons (waiter)==
Server processes that run continuously, wait idle at the background for a request (`httpd, sshd` )
#### ==** Threads==
If a process is a single office room, then threads are workers inside that office room. (`gnome-terminal-server`)
#### ==** Kernel Threads==
Belong to OS kernel, maintain the whole system. (`kthreadd, migration`)


## * Process Scheduling and States
One of kernel's functions is ==scheduler==, it shifts processes on and off, and set time limit to each of the processes.

==**Running state**== can mean it is actually running (using CPU) or waiting for share of time from kernel. All of the processes here reside on ==**run queue**.==

## * Process and Thread IDs
OS is building manager for hardware to enable user to run application programs.

OS keeps track of processes by assigning ==PID (Process ID)==. PID are usually ordered based on born time.

#### ** ID Type
==Process ID, Parent Process ID== (process that starts the process), ==Thread ID== (unique ID for a thread inside a process)

## ==* Terminating a Process==
To terminate a process you can use:
```bash
# use this for force kill
kill -SIGKILL <pid>
kill -9 <pid>
```

#### ** How to get `pid`
```bash
ps aux # to look at all programs running
ps aux | grep firefox
kill <pid> # graceful exit
```
`ps` is process status, `aux` is all processes, user-oriented, include processes that are not attached to any terminal.

## ==* User and Group IDs==
**Real User ID (RUID) / Real Group ID (RGID)**, identifies the user who started the process.

**Effective User ID (EUID) / Effective Group ID (EGID)** determines the access rights of the users. Can be root (0) or regular user (1000)

A user can join one or more groups.

## * More About Priorities
CPU can only accommodate on task at a time, so priority is important.

Priority is can be set by nice value. The lower nice value, the higher the priority. In Linux, nice value of `-20` is the lowest, `+19` is the highest.

==**Hard real-time** > **Real time**> **Nice Value**==

Real time priority are jobs that need fast response, while hard real time priority are jobs that "if it fails, whole system may fail"


## ==* Set Priorities==
```bash
ps
ps lf # l: long format with nice value details, f: full format, draw parent-child process
ps aux # show entire system
```

==Set priorities by==
```bash
renice +5 <pid> # +5 is the new nice value
```

you can't increase priority if you don't have access to it

#### ** by GUI
```bash
gnome-system-monitor
```
