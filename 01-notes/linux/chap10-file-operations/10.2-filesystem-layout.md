## * Overview of User Home Directories
==Each user has a home directory==, under `/home` or `/root` for root user.

==You can create subdirectories under `/home` for multiple departments== or functions, for example, `/home/faculty`, `/home/students`, `/home/staff.`


## * The `/bin` and `sbin` Directories
==Binary Directory contains many essential executable program files (binaries)==. 
==Most vitals tools are here, it must work under all conditions==, while booting up, while single-user mode (emergency repair state), while every user on the machine.

Some commands stored here is `cat, cp, ls, mv, ps, rm`

#### ==** `/bin`==
Stores essential commands required by all system users

#### ==** `/sbin`==
Stores essential commands required by system administration

```bash
ls -F /bin /sbin
```

#### ==** `/usr/bin` and `/usr/sbin`==
Less essential commands are stored in here.

In modern Ubuntu, ==`/bin` and `/sbin` are pointing to `/usr/bin` and `/usr/sbin`==, the real binary program is here.


## ==* The `/proc` Filesystem==
Filesystems mounted at `/proc` are called ==pseudo-filesystems==, because they have no permanent presence on the disk.

`/proc` holds ==virtual files== (behave like a normal file to commands but not saved on hard drive). ==When you read the file, kernel makes up the content right at that moment.==

==`/proc` mirror kernel settings==, kernel's live internal runtime information.

```bash
/proc
/proc/cpuinfo
/proc/interrupts
/proc/meminfo
/proc/mounts
/proc/partitions
/proc/version

# subdirectories
/proc/<Process-ID-#>
/proc/sys
```

## ==* The `/dev` Directory==
This directory holds ==device nodes==, also virtual files. These files ==act as a bridge, programs talk to hardware/software== by reading these files.

During system boot, ==kernel mounts virtual filesystem (`devtmpfs`) to `/dev`==, originally `/dev` is empty.
#### ==** `udev`==
It is a Linux system service, when kernel detects hardware, `udev` creates `/dev/sda,....`. Device nodes appear and disappear automatically.


## ==* The `/var` Directory==
This directory stores files that are ==expected to change in size and content (dynamic)==, they are ==system's changing files== (not user owned), it ==lives on your hard disk, they must survive reboot.==

```bash
/var/log # system log files
/var/lib # packages and database files
/var/spool # /var/spool
/var/tmp # /var/tmp
/var/cache # system-wide cache files
/var/ftp # FTP service
/var/www # HTTP web service
```

#### ==** Cache Files==
It is a temporary copy of data which are frequently-used, to make things faster.

## ==* The `/etc` Directory==
Stands for et cetera

It is ==home for system configuration files.== ==No binary programs== (source code that has been compiles). These files ==must apply for every user.==

Only superuser can modify files here

```bash
/etc/resolv.conf # where to go on network to obtain host name
/etc/fstab # define which fystems mount automatically at boot
/etc/exports # NFS shared folders configuration
/etc/passwd # user account information
/etc/crontab # system cron job config
/etc/shells # list valid command shells

```

#### ==** Configuration Files Definition==
They are text files that store settings/rules for how you Linux system and services behave.


## ==* The `/boot` Directory==
It contains ==few essential files to boot the system==. Each files has a ==kernel version appended to its name.==

#### ==** 4 Files inside `/boot` directory==
1. `vmlinuz` -> Compressed kernel for booting
2. `initramfs` -> Initial ram filesystem for booting, or called as `initrd`
3. `config` -> Kernel configuration file for debugging and bookkeeping
4. `System.map` -> Kernel symbol table for debugging


## * The `/lib` and `/lib64` Directories
==Contains libraries (common code shared by applications) for essential programs in `/bin` and `/sbin.`==

It is also called to ==contain Share objects (`.so`)== as it be used to run programs with the code.

Can be ==32-bit or 64-bit==

#### ==** Kernel Module==
Kernel has built-in code, kernel module is the extra piece, often ==device drivers==. Driver is the code that lets kernel to talk with hardware. It is important to ==not require booting when load or unload a device.==

Stored in
==`/lib/modules/*`==

## * Removable Media: the ==`/media`, `/run`, and `/mnt` Directories==
For USB drives, CDs, and DVDs

These directories will be the ==root of mount points for plugged-in medias.==

At first, everything was done under `/media`, but in modern Linux, it is done ==under `/run`==

`/run/media/student/myusbdrive` -> USB pen drive labelled `myusbdrive` for a user named student

==`/mnt`== -> mount, USB drive, NFS, Loopback Filesystem

## * Additional Directories Under /:
#### ** `/opt`, optional
Optional application software packages You ==install some commercial software manually, it will be stored here. Any user can launch this software.==

#### ** `/sys`, system
Virtual files to ==give info about system and hardware,== while `/proc` give info about running processes and general system status, `/sys` provide info about hardware devices, kernel modules

#### ** `/srv`, service
==Data files for server service==s, for network servers


#### ** `/tmp`
==Temporary files==

#### ** `/usr`
Multi-user applications, utilities and data, ==most of the system software lives here.==


## * ==The `/usr` Directory Tree==
Contains theoretically non-essential programs (not needed to boot the system)

```bash
/usr/include # header files to compile applications
/usr/lib 
/usr/lib64 # non-essential system binearies, like system daemons and scripts
/usr/sbin
/usr/share # non-executable resources such as man-pages, icons, themes
/usr/src # source code files, for example, kernel source code
/usr/local # small open-source tools i compile myself, split into /bin /lib /share
/usr/bin 
```
