## * Backing Up Data
by
```bash
cp # simple
rsync # more robust / strong
```
#### ==** What is an Archive==
An archive is single file that wraps many files and folders.
#### ** `cp`
`cp` ==cannot be used to copy by NFS.==
#### ** `rsync`
`rsync` is ==more efficient==, because it avoid duplicated files and it only copies parts of files that have actually changed.

It can be used to copy files from one machine to another by NFS. Locations are designated in `target:path` form.

Target in `someone@host` if both users are different.

## ==* Using `rsync`==
```bash
rsync sourcefile destinationfile
rsync -r project-X archive-machine:archives/project-X
```

#### ==** Good Combination==
```bash
rsync --progress -avrxH --delete sourcedir destdir
# a, archive mode, keep content and properties
# v, verbose, print what files rsync is processing
# r, recursive
# x, do not cross filesystem boundaries, skip /proc, /dev
# -H, preserve hard links
# --delete, delete files in destdir than no longer in sourcedir
# --progress, show percentage
```

#### ** `-r option`
This recursive option is really important if your path is a directory.
#### ** Safety Precaution
```bash
rsync -dry-run # to test
```

## * Compressing Data
==**Methods to Perform Compression**==
```bash
gzip # most frequent
bzip2 # produce files significantly smaller than gzip
xz # most space-efficient in Linux
zip # often used to examine and decompress archives from other OS
```

#### ==** Use `tar`==
Use it to group files and folders in an archive before compress.


## ==* Compress Data by `gzip`==
`gzip`, GNU zip
`.gz` extension

```bash
gzip * # compress all files in the current directory
gzip -r projectX # compress all files inside projectX directory recursively
gunzip foo # decompress file foo, same like gzip -d
```

## ==* Compress Data by `bzip2`==
Similar to `gzip`, but result in smaller files, with trade of the speed of work.
`.bz2` extension

```bash
bzip2 *
bunzip2 *.bz2 # same like bzip2 -d
```

## ==* Compress Data by `xz`==
Most space-efficient compression utility
`.xz` extension

```bash
xz *
xz foo # decompresses foo into foo.xz and removes fo
xz -dk bar.xz # d, means don't delete input files, decompress but does not delete the compressed file
xz -dcf a.txt b.txt.xz > abcd.txt
# c, write output on standard output not on disk, f, means force, overwrite if needed
xz -d *.xz

```

## ==* Handling Files Using Zip==
`zip` not often use to compress in Linux, but it may be needed to examine and decompress files from other OS.

```bash
zip backup * # compress all files in current directory, bundles them together, and place them to backup.zip as an archive
zip -r backup.zip ~ # archives your login directory
unzip backup.zip # extract all files in backup.zip all place them in current directory
```

## ==* Archiving and Compressing Data by `tar`==
`tar` stood for tape archive
```bash
tar xvf mydir.tar # x means extract, v means verbose, f means specify archive file
tar zcvf mydir.tar.gz # c means create new archieve, z means gzip compression
tar jcvf mydir.tar.bz2 # new archive and compress with bz2
tar Jcvf mydir.tar.xz # new archive and compress with xz
tar xvf mydir.tar.gz # extract file
```

You can use `-` or not, not really necessary

You can separate stages by

```bash
tar cvf mydir.tar mydir ; gzip mydir.tar
gunzip mydir.tar.gz ; tar xvf mydir.tar
```

## * Disk-to-Disk Copying (dd)
Copy every byte, empty space, boot area, metadata, exact clone

#### ==** Why use `dd` instead of `rsync`==
`rsync` is used for file-level backup, dd is used for block-level raw copy. `rsync` understands what real files are, so it will skip empty blocks.

`dd` copies the whole blocks. Fun fact: when delete a data from a block, it just label the block as "free", but the data is not deleted, it is kept inside the block. Forensics can take the deleted data there.

#### ==** What are blocks?==
Blocks are fixed-size chunks of bytes that hardware reads/writes as one unit, you can think of it as a tiny slot. 

#### ** MBR
MBR does not live inside filesystem, it sits in sector 0, the very first 512 bytes of the raw device.

```bash
# First check your disk (a block device)
lsblk # list block devices
```

```bash
dd if=/dev/sda of=sda.mbr bs=512 count=1
# if, input file, where to read from
# of, output file, where to write to
# bs, block size
# count, how many blocks to copy
```

Check it by
```bash
file sda.mbr # look at the type of the file
xxd sda.mbr # show raw bytes in hex
```

#### ** What a Disk is ?
It is physical storage that stores data, in Linux, it is called as block device. Usually a laptop has only 1 main storage device, it can be split into multiple partitions
